# Q叔公众号图文写作

把输入直接做成能读、能看、能继续修改的完整文章。默认作者是 Q叔，账号为「Q叔未来事务所」，当前用户另有要求时以新要求为准。参考卡兹克的观察、验证、渐进叙述与共情方法；声音和经历属于用户。

## 开始时

1. 读取 [写作方法](references/writing-method.md) 与 [已确认偏好](references/preferences.md)。第一次为这个用户写稿、修改节奏或结尾时，同时读 [案例结构与配图节奏](references/case-study.md)。
2. 若 [项目连接](references/project-connection.json) 中的项目存在，先读取它当前的写作偏好、反馈证据和协作索引。相关 Page 有后续修改时，先读取正文与批注、同步真实快照，再写稿。连接不可用时，使用技能自带的偏好和案例继续工作。
3. 用户给了链接就主动打开，给了文件就读文件。先研究可得材料和获取配图，不要求用户复述已经给出的内容。通常直接完成整稿；只有缺失的信息会改变核心事实、归属或真实个人经历时，才简短询问并继续独立工作。

## 从选题到图文稿

写新品发布或实际体验评测、社会事件需要接到读者、稿件缺少理解递进或自然共鸣，或用户要求研究思考逻辑时，读取 [写作思考图谱](references/thinking-graph.md)，按题材选择有材料支撑的关系。图谱提供问题、条件与原文定位；不把它变成固定章节，也不将原作者的经历或未核验判断移植给用户。

**先抓一件值得写的事。** 链接可以是入口，而非文章主线。找到一个具体发现、疑问、变化或读者处境，用一句内部工作句说明“读完后，会多知道什么、重新感受到什么”。已有切入点优先保留。材料不足以撑长篇就写短篇，不预设固定字数。

**主动研究与验证。** 按 [素材与配图流程](references/materials-and-images.md) 阅读原页面、官方文档及相关材料。把事实、已实际验证的结果、作者感受、推测分别记下。产品可以体验时，验证最能支撑文章的一个关键动作，保存截图。未执行的动作不能写成实测；代理做过的动作也不能自动变成用户亲身经历。

**让下一段有来处。** 从可看见的对象或具体场景开始，让读者跟着看到、理解、尝试，再抵达意义。每段增加一个事实、可用信息、疑问的答案、观察或感受变化。读者尚未进入场景时不要一口气倾倒结论；已明白的意思也不换三个说法重复讲。

**把共鸣写在具体处境里。** 从前文已展示的体验向外走一步，解释它为什么让人心情发生变化。需要对照时先承认另一种选择的便利与合理，再回到人的真实需要。末尾可以落在一个小愿望、重新理解或眼前细节上，不必布置行动作业、喊口号或强制反转。

**文字与图片一起安排。** 写作时就获取能承担叙述的图片，不等正文写完再随机配图。每张图回答一个明确问题，图旁文字只补它没表达的内容。实际文件已保存、打开检查且来源可追溯后，才放进交付稿。变化过程优先真实 GIF 或可用录屏。图数、图位与停顿取决于选题，不固定复用案例的九张图。

## 交付标准

在当前项目或用户指定目录下，给每个新选题建独立文件夹，保存：

- `文章.md`：一个选定标题与完整图文正文，图片引用实际文件；正文可直接阅读和修改。
- `预览.html`：15px 正文、1.9 行高、轻量留白与按作用设置的图片宽度。使用 `scripts/build_article.py` 生成；不要追加固定品牌 banner、教程目录或宣传尾巴。
- `配图/` 与 `配图来源.json`：正文使用的真实图片或动图、来源、承担的段落作用、原图或处理说明；封面按主题选取，单独标记用途。
- `素材与核验.md`：关键事实的直接来源、日期、已验证动作与未验证边界。研究说明放在此文件，正文保留必要出处即可。

按 [图文交付](references/materials-and-images.md#交付与脚本) 建配图清单和运行脚本；生成后逐一检查实际图片、动图及关键图位。脚本只校验文件、图文顺序与排版，不能替代事实核验或文笔判断。

可编辑 Page 能创建时，按可用的 Pages 技能与工具把**本次新稿**建立为可编辑、可批注文档，链接到本地文件；保留既有文档身份与批注。使用 `open_in_codex` 在右侧展示 Page 或图文预览。工具返回 queued 时仅说明已请求打开，不声称已经看到实际画面。正文和完整素材先完成；某种展示方式不可用时保留本地完整交付并说明具体限制。

最终回复以文章或打开的预览为主，简短附上可编辑稿和必要事实边界，不把选题分析、质检表和长篇研究过程当成成稿。

## 改稿与后续学习

按 [改稿与可选发布](references/revision-and-publishing.md) 保存真实修改、批注、版本差异和依据。优先继承用户保留的叙述；仅修改本轮指出的问题。区分明确反馈、观测到的改动和代理猜测，未核验作者的快照保持 unknown。新偏好须写适用范围；本轮代理改写不是用户的文字样本。

用户要求完整图文稿时，主动研究、搜集配图、完成整稿。外部发布依照当次明确要求或可核验的持续授权进行；不能从“给我一篇完整文章”自行推出群发、公开分享或替换已有草稿。包含私人素材的 GitHub 备份须使用用户已授权的私有仓库，上传前验证 private；安装本技能不构成备份授权。

## 出稿前通读

- 开头能否跟着看进去，中段是否继续增加信息，删掉重复解释后能否更顺？
- 相邻两段的因果是否成立，是否为了升华临时引进无关话题？
- 去掉口语词、自嘲和短句排版后，是否仍有具体材料与可识别的感受？
- 结尾的感受是否由前文支撑，读者能否认出自己的处境，而非被要求接受大道理？
- 事实、经历、引语、价格与功能是否有对应依据？图片能否实际打开，GIF 是否保留动画，来源是否匹配？

发现断点就修改后再交付。避免拿更长的篇幅、更多例子或更多语气词来代替真正的推进。
