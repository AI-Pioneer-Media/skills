# 素材、配图与完整交付

## 接到不同输入

| 输入 | 主动完成的研究 | 可用图像 |
| --- | --- | --- |
| 网站、产品链接 | 打开实际页面；理解主功能；检查入口、使用门槛及关键操作；按需要读官方文档 | 实际页面、关键动作、结果、必要的变化过程 |
| 新闻、发布链接 | 找原始公告；核对日期、功能范围、价格和数字；补足影响判断所需证据 | 官方发布图、文档局部、可核验的结果或原始数据图 |
| 论文、PDF、报告 | 读正文和关键图表；辨别实验、假设、结果与作者解释 | 有页码及来源的原图、准确重绘且标记的图解 |
| 视频、播客、访谈 | 获取可用原视频或转录；关键原话核对说话人及时间；无法核对的引用不加引号 | 真实访谈画面、已提供材料、支持关键说法的证据 |
| 一句选题、想法 | 从选题寻找具体对象和原始材料；自行决定一个可写角度；核心个人事实缺失时才询问 | 对象的真实图片、场景材料或明确标记的解释图 |
| 现有稿、截图、零散笔记 | 理解原来想说什么；优先保留声音和已核实细节；读取当前可编辑稿及批注 | 用户已有素材优先，补缺少而有作用的图 |

把材料写成事实清单：主张、直接来源、来源日期、核验日期、状态（已读／已实测／推测／待确认）。过时的产品能力不可照搬。原文带有广告、作者推测或未经验证的行业概括时，不把它们当独立证据。

产品体验不需要测试每个功能。围绕文章主线完成一个足以支撑核心说法的动作。复制代码、独立运行与接入真实产品是不同程度的验证，写准确。访问不足时，可以用已获得的真实资料调整角度，不编造完整体验。

## 图片承担的作用

- **建立对象**：读者第一次看到陌生东西时，用真实页面或对象图。
- **展示变化**：效果靠时间发生时，真实 GIF 或录屏比三个同义评价更有用。
- **证明动作与结果**：代码复制、生成效果或参数变化，配实际操作或结果图。
- **缩短解释**：多个场景可以用一张清晰总览；复杂关系用准确图解。
- **提供感受细节**：后段要谈哪处用心，就让读者看到那处细节。

先决定图的作用，再找图。优先来源页面、官方素材、用户已提供文件、实际操作截图；通用图片搜索用于寻找相关原始材料。点开候选确认内容、出处和分辨率，不能只凭搜索摘要或相似外观采用。需要解释图时可以自行制作，注明“图解”；生成式示意不能冒充产品界面、新闻现场或实测结果。

不要用装饰图填满文章。操作密集的中段可多图，结尾可连续几段文字。某张图并未增加理解、证据或感受时，就不必放。无需每200字一图、每篇九图或结尾必有封底。

## 获取与检查

用当前获准的网络、连接器或浏览器工具读取来源与获取媒体。浏览器使用先读工具文档；只用获准的界面操作，不能为截图改用未获准的浏览器或绕过被拒绝的动作。网页动画需来自真实播放过程；不能把几张静态图的交叉淡入称为产品真实动画。

用户已要求主动搜集配图，实际可取得的素材就自己保存、检查和插入，不回问“这里要配什么图”。图像文件存到文章目录，检查文件签名或解码、画面是否符合所述内容、文本是否清晰、是否错误截到菜单或空白。GIF 检查帧数和变化；有可用视觉预览时检查实际播放，文件帧数核对不能宣称微信客户端视觉检查。

保留原始图。必要的格式转换保留内容，注明转换；裁切或标注保留处理说明。用当前适用的图像技能及工具做图像编辑。不能更改截图中的价格、指标、按钮、日期等事实来迎合正文。

某个关键页面或媒体确实不可得时，用可核验的来源图、准确说明图或调整写法完成能完成的部分。交付中明示哪一项缺失和影响，不留下“待放GIF”的假成稿，也不把来源文件地址当作已下载的图片。

## 交付与脚本

建议目录：

```text
选题目录/
  文章.md
  预览.html
  公众号正文.html
  素材与核验.md
  配图来源.json
  配图/
  图文校验.json
```

`文章.md` 首行使用一个 `# 标题`；正文使用实际图片相对路径。素材清单的文件路径以 `配图来源.json` 所在目录为基准。脚本支持 PNG、JPEG、GIF、WebP 等 Pillow 可读取格式，确认图片真实可解码，并检测链接是否为本地实际文件。

清单格式（下面只是字段示例，真实交付填实际值）：

```json
{
  "schema_version": 1,
  "images": [
    {
      "file": "配图/01-结果.png",
      "source_url": "https://example.com/actual-source-page",
      "kind": "screenshot",
      "role": "让读者看见正文提到的实际结果",
      "display_width": 560,
      "source_note": "实际截图，未改动界面内容"
    }
  ],
  "cover": null
}
```

`kind` 可用 `screenshot`、`official-image`、`recorded-animation`、`user-provided`、`diagram`、`generated`。前三类填实际 HTTP(S) 来源；用户文件可用 `source_note` 说明来源；图解或生成式示意注明制作方法。GIF 标记为动画的，至少两帧。封面如有，使用同样记录格式放在 `cover`，不会自动插入正文。

运行：

```bash
python3 scripts/build_article.py --markdown /绝对路径/文章.md --assets /绝对路径/配图来源.json --output /绝对路径/预览.html --wechat-body /绝对路径/公众号正文.html --report /绝对路径/图文校验.json
```

脚本路径相对于技能目录。依赖见 `scripts/requirements.txt`；优先使用当前可用的工作区运行时，缺少依赖时安装到任务专用环境，不更改全局环境。用 `--help` 查看参数。

已连接的 Page 可以直接使用真实 `read_page.structuredContent` 快照：把图片记录补上实际 `reference`，运行 `--snapshot /绝对路径/页面.json` 代替 `--markdown`。脚本按真实块顺序渲染，保留空段落与可读图片宽度元数据；不写回 Page。只有用户明确要求纯文字时才使用 `--allow-no-images`。

生成后，在可用的预览工具中检查开场第一组图片、操作段和结尾图位，核对手机宽度下是否能读。可以使用 `open_in_codex` 右侧打开交付；浏览器或工具实际检查失败时，诚实记录检查范围，不把 HTML 校验说成客户端排版实测。
