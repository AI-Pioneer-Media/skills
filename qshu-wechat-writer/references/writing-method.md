# 如何形成这种叙述

目标读感：一个有兴趣、有判断的人，带我看见一件具体的事，知道它怎么回事、能怎么用，读着读着开始关心它。作者的姿态是并肩分享，读者保有自己的判断。

## 从第一性原理推导

读者进入文章时还没有作者的兴趣、背景或情绪。先交付可观察的东西，才能建立共同对象。具体画面、动作和结果降低理解成本；信息围绕读者下一步自然产生的问题出现，才能维持注意力。感受依附在共同对象上，才有理由向外延伸。因此：

`可感知的发现 → 随之产生的问题 → 材料或验证给出的答案 → 人的处境得到照亮 → 合乎前文的感受`

这是一条支撑关系，可前后交织，不是五段模板。新闻可能从一个变化起步，人物故事可能从一次选择起步，方法文章可能从一个真实卡点起步。新材料负责推进，停顿让读者消化刚看到的东西。

“慢”指逐渐建立共同感受，并不等于铺垫长；“信息密度”指每次继续读都有收获，并不等于连续列参数。两者可以同时做到。

## 选题和开头

找到最小的可讲述对象：一次复制、一个错误提示、一段回复、一幅画的变化、一项过去做不到而现在能做的事。先写这个对象，再决定需不需要行业背景。用户给出的切入点有材料支撑就保留。

开头给读者一个可跟随的入口。只给足当前需要知道的信息，随后在动作、图片或问题上补充背景。不要为抓眼球承诺“彻底改变世界”，也不要为了个人叙事伪造“凌晨三点”“刚花了多少钱”“我朋友昨天”。没有作者现场时，照样可以从真实观察和可追溯材料写一篇好文章。

标题从文章真正打动人的地方提炼，既让人知道在说什么，也留一点想读的空间。标题完成后回到正文核对承诺，避免标题宏大、正文只是罗列功能。给用户整稿时选定一个标题即可；用户要求候选再列候选。

## 推进，而不是累加

写稿时给段落做临时标签：事实、观察、动作、结果、疑問、解释、感受变化。标签留在工作笔记，不进入正文。若连续几段只把同一个判断换词表达，合并或删除。

转场自检：读完上一段，我自然会想知道下一段这件事吗？把“于是”“这让我意识到”“更重要的是”删掉，联系还成立吗？不成立就补真实材料、换位置或舍弃那条支线。

实用内容本身有价值。明确说出入口、动作、结果和适用场景，不必再安排哲学任务。中段若已证明好用，就进入读者尚未知道的东西；不重复同类案例来加长文章。

图也是推进：展示结果后，文字可以谈结果哪里特别；展示代码入口后，文字说明复制到什么、验证到了哪一步；动态图展示了变化，文字就不必逐帧复述整段动画。

### 删掉语气词还不够

去掉机械旁白后，仍要检查推理是否完整。读者起初不知道什么？这一段回答了什么？下一份材料怎样补充或修正理解？不同主题不能只因素材先后出现就被写成因果。保留解释需要的理由、条件和分歧，减少没有依据的比较。

## 真实的人与声音

用具体感受表达好恶，例如关注哪里好看、哪个动作省心、哪一刻让人愿意停留。少写无对象的“震撼”“治愈”“重新定义”。短自嘲、括号反应、长短句可按当前材料自然出现，不设数量指标，也不借口“人味”故意制造语病。

“我”有证据边界：用户提供的真实经历可以代笔；代理操作需准确标识为本次代查或验证，不能补成用户记忆。无法确认身份和经历时，选观察型写法，或只询问一个不可替代的事实。作者身份不借用参考作者，不能复制其私人关系、职业年限、付费记录或苦难。

尊重用户留下的声音。用户明确保留了某个松弛表达，局部改稿不替它统一成严谨报告。格式规范化、事实订正与风格取舍分别记录。

## 结尾与共鸣

先问：这件事照顾了哪个熟悉的愿望、烦恼或感受？前文有哪些可指认的细节，让这个感受成立？回答得出来再往外写，最多沿同一个关心多走必要的几步。

小事也能抵达意义。一个人认真做了不影响任务结果的细节，可以让读者感到被用心对待；人的选择可以让工具的意义变得具体。升华靠这种联系，不靠结尾突然加入“在AI时代，我们所有人都应该”。

有对照时，先承认对照对象解决的问题。Agent 代办下载很方便，不足以证明生活会无聊；Markdown 便于机器读取，不足以证明企业已放弃审美。文章写出自己的取舍与愿望即可，不把偏好冒充行业结论。

结尾的落点随选题变化：重新理解一个小场景、一个合乎材料的愿望、一次关系的变化、一个有依据的判断，都可以。花园、人生三万天、“等待也很美”只属于这篇案例。不固定名人名言、金句数量、回扣图或点赞号召。

## 这轮失败案例如何修

### Copy code 后人为搭桥

被指出的问题：从“代码能复制”连续写“接入AI有起点 → 我要选择页面是什么样 → 花园还是帆船 → 选择必须自己做 → Dawn”。它没有补充新的产品信息，后一个话题也不是前一个动作自然产生的问题。

修法：用实际复制结果完成实用信息；需要体验感受时，回到已展示的画面。确实涉及设计选择的新选题，再用真实选择过程写，不把选择话题硬塞进每一次复制代码。

### 压缩后开头太急

被指出的问题：为了提高信息量，开头连续抛产品、代码、场景、行业趋势，读者还没看到对象就被要求理解价值。

修法：保留能进入场景的最少几句，把图放在观察节点上，等读者看见之后再说下一步。减掉重复解释，保留必要的认识过程和停顿。

### 为了慢而重复举例

被指出的问题：扩展更多绘画步骤、另一幅作品和同样的评价，让长度增加，主线没有前进。

修法：只保留最能让读者看懂的一个过程；其他作品用总览承担信息，下一段推进用途或感受。每张图、每个案例都需有独立作用。

### 行业判断突然抬高姿态

被指出的问题：“越来越多企业只为Agent做网站，不迎合人类审美”从小发现跳到未经证明的行业结论，接着教读者给用户惊喜。

修法：先让人认出等结果的普通心情，承认代劳方便，再写仍愿意亲自看见的东西。最后落到被认真对待的感受，不把读者变成必须接受建议的产品负责人。

## 从实际原文借鉴什么

本项目研究过卡兹克的具体原文；这里只记录结构观察，不把参考作者的故事写成Q叔的经历：

- 《Lovart悄悄上的这个新功能，就是我心中设计的神。》：前面一直在演示改字，后面关于当年改不了一个字的记忆，有同一件事支撑。
- 《AI看不到的爱心，成了最棒的AI检测器。》：疑问来自实际图像测试，原理解释又回到开头的图，再连接人的体验。
- 《假扮AI的17岁男高中生，用回复治愈了整个B站。》：共情由怎样回复、受到伤害和朋友行动累积，结尾收回一个普通的交朋友愿望。

原文链接与可读的本地归档位置见 `project-connection.json`。这些是选定作品的观察，不是作者每篇都遵守的公式。若新稿需要继续学习作者的推进，选与当前题材相关的实际原文细读，记录问题、材料、转场、情绪出现的位置，避免只数“我”、感叹号或短句。
