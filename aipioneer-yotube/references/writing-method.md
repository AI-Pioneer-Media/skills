# AI Pioneer YouTube 写作方法

## 1. 一篇文章只解决一个问题

开写前先完成一句话：

> 这篇文章帮助哪一类读者，在什么情境下，改变哪一个判断或行动？

凡是不能服务这句话的趣闻、履历、旁支观点和相似案例都删除或压缩。视频内容很多不等于文章要全部收录。

## 2. 从“访谈摘要”改成“判断链”

先从字幕中提取四类素材：

1. 反常识判断；
2. 能证明判断的故事、动作、数字或失败；
3. 解释结果为何发生的机制；
4. 读者能够采用的检查方法或动作。

再按照因果关系组织章节。推荐骨架不是固定章节数，而是连续推进：

`读者冲突 → 核心判断 → 判断边界 → 真实案例 → 底层机制 → 更大影响 → 行动`

每章写完后补一句桥梁：上一章解决了什么，但还缺什么，因此下一章必须出现。桥梁要推进问题，不能只是“接下来我们看看”。

## 3. 开场五步

1. 用读者正在面对的真实冲突开场；
2. 交代视频场景和说话者为何值得听；
3. 给出最反常识的判断；
4. 说明这个判断容易被怎样误解；
5. 承诺文章会解决的具体问题。

开场不要先写人物履历，不用“最近我看了一段很有启发的视频”。视频缩略图和图注放在开场正文之前，让读者先确认素材来源。

## 4. 章节内部结构

一章至少包含以下四项中的三项：

- **结论：**这一章要改变读者什么判断；
- **证据：**视频里的场景、原话含义、数据或故事；
- **机制：**为什么会发生，而不是只说发生了；
- **影响：**这对创业者、产品经理、工程师或普通读者意味着什么。

不能连续两屏只有抽象观点。数字必须解释量级变化；故事必须落到机制；方法必须有适用边界。

## 5. “有血有肉”的最低标准

重要章节至少给出一种可核验细节：人物、动作、场景、时间跨度、成本、速度、成功率、失败反馈或具体产物。

优先写：

- “每位用户每天只用3分钟，服务器可能翻倍”；
- “一次模拟要一整晚，近似评价器快30万倍”；
- “Agent走到第30—40步后开始偏航”。

少写：

- “这非常重要”；
- “带来巨大影响”；
- “值得我们深思”。

抽象形容词不能代替事实。

## 6. 语言偏好

- 一段只承载一个观点或一个动作；长句中出现三层以上转折时拆段。
- 用直接动词表达判断，例如“吃掉、撞上、干掉、压缩、筛掉”，但不能把作者改写的狠话伪装成人物原话。
- 允许短句制造停顿，避免每段都使用同样长度。
- 删除无信息的情绪词，如“很残酷、令人震撼、堪称颠覆”；数字和场景已经有力量时不要再加形容词。
- 概念首次出现时立刻用动作解释。例如“评价闭环”后面要写清“提出、运行、打分、保留、再尝试”。
- 英文专名保持准确；公司、模型和产品不可混为一谈。

## 7. 结尾

结尾先把全文案例收束成一条可复述的路径，再给一个具体动作。优先使用填空、自检或今天就能完成的选择；不要以“大家怎么看”“评论区聊聊”代替结论。

适合的方法：

1. 当前基线是多少；
2. 现有系统缺什么；
3. 如何快速验证；
4. 做成后谁会发生什么改变。

最后一句要回到标题提出的问题，并留下一个比“是否同意”更有分量的选择。

## 8. 事实与观点分层

- 视频事实：明确写“某人在访谈中回忆/提到”。
- 官方事实：给出论文或机构页面。
- 作者判断：使用“这意味着、对创业者更有用的是”，不要套进引号。
- 证据不足：删掉具体会议名、日期或夸大程度，保留能确认的上位事实。
