# 样本依据与迁移示例

样本：[APPSO 发布会报道](https://mp.weixin.qq.com/s/d2gCFkLcrWDCJ8dDS54Lyw)，标题为《刚刚，ChatGPT 一夜抄完半个 AI 圈，现场演示频频翻车》。本参考根据会话中取得的文本分析，适合说明写作机制；涉及新闻事实仍需在新稿中单独核验。

## 能观察到的结构

1. 标题选择大众熟悉的 ChatGPT，结合时效、竞争关系和演示意外，提供多个点击理由。
2. 开头从付费套餐权益变化切入，把发布会变成用户关心的消费问题。
3. 主体先讲主要产品的运行过程，再讲模型成本及配套工具，最后讲分发入口。产品较多，但用少量大章节串联。
4. 人物演示、界面动作、现场故障与公开反应穿插在产品解释之间，形成阅读节奏。
5. 真实界面图跟随操作叙述，读者可以通过图片理解产品如何运行。

上述观察支持“更易理解、更有悬念”等编辑判断，不能单独证明它获得更高点击率或完读率。原会话的粗略图片计数包含页尾、页面元素，不能把它固化为有效配图的精确标准。单篇样本也不能代表整个账号的所有写法。

## 可迁移的编辑动作

### 参数开头改成成果开头

假设材料已证实某工具可从一份销售表生成演示文稿：

平铺：某模型支持长上下文、多工具协作和文档生成。

改写：把销售表交给它，几分钟后拿到一份能修改的汇报稿。真正需要检查的是：结论有没有算错，图表是否引用了正确的数据。

使用前必须有实际输出、时间依据和适用条件；没有实测时明确写“官方演示中”，不能伪装成作者体验。

### 价格新闻改成读者能理解的账

先说同样一项任务的成本或同样预算能尝试多少次，再给 API 计费。若只有每 Token 单价，说明“同等输入输出量下”的理论比较，不推断任务总成本或订阅费用。

### 图片从配套材料变成故事的一部分

“介绍功能 + 发布页截图”可改为“用户输入 + 操作界面 + 输出结果”。截图下说明一个最值得看的变化。复杂基准图只保留与主线直接有关的结果，说明测试条件和不适用的外推。

### 用可靠的意外保持兴趣

演示遇到延迟时，写清卡住的步骤、是否恢复及官方解释。正文可以据此讨论使用体验；不能为配合标题把偶发界面问题扩写成模型全面失效。

## 练习时应能通过的三个场景

- 用户要求写一个降价模型：围绕实际用途与价格口径写，不因参考稿涵盖大会就擅自扩写全部新品。
- 官方材料没有翻车或争议：用真实成果和用户问题制造阅读动力，不编造竞争冲突。
- 用户要求分析爆款但没有后台数据：指出可观察的标题与叙事手法，把效果解释写成假设，不声称算法偏爱或用户普遍认可。
